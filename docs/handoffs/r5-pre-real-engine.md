## What was built

### Work Package 1 — Backend-Aware Process Quiescence (§7.10, §7.11)
- `runtime/execution.py`: Added `ProcessQuiescenceResult` model.
- Added `quiesce(session, process, *, grace_seconds)` to `ExecutionBackend`.
- In `SubprocessEngine.execute()`: Main process exit is followed by mandatory backend quiescence. Any lingering descendants trigger SIGTERM, grace period, and SIGKILL.
- If quiescence fails or times out, the attempt fails with `AttemptOutcome.ENGINE_EXECUTION_FAILURE` before proposal import can begin.

### Work Package 2 — Writable-Entry Quota Accounting (§7.7, §7.8)
- Replaced `max_writable_files` with `max_writable_entries` across `SubprocessPolicy` and runtime contracts (bumped runtime contract version to `1.6`).
- Writable-entry accounting scans `output/`, `scratch/`, `home/`, and `tmp/` without following symlinks.
- Every regular file, directory, symlink, FIFO, socket, and special device counts as 1 entry toward `max_writable_entries`.
- Apparent sizes are counted for regular files. Exceeding quota immediately halts execution with `ResourceLimitCode.MAX_WRITABLE_ENTRY_COUNT`.

### Work Package 3 — Trusted Subprocess Launcher & Kernel RLIMITs (§7.5, §7.6)
- Created `runtime/trusted_launcher.py`: Standalone, zero-dependency bootstrap executed before the agent worker script.
- Configured via `LauncherPolicy` and `launcher/policy.json`.
- Applies POSIX kernel resource limits (`RLIMIT_NOFILE` via `max_open_files`, `RLIMIT_CPU` via `max_cpu_seconds`, `RLIMIT_AS` via `max_address_space_bytes`).
- `RLIMIT_NPROC` is documented as non-authoritative on Linux (process tree monitoring remains primary).
- Drops ambient privileges (`PR_SET_NO_NEW_PRIVS`, setsid) and executes worker via `os.execvpe`.

### Work Package 4 — Credential Lease Lifecycle & Execution-Root Isolation (§8.1, §8.2)
- Added `CredentialLease` dataclass with mandatory context-manager cleanup (`cleanup()`).
- File credentials are written strictly inside the external attempt execution root (`credentials/`) with `0700` directory and `0600` file permissions.
- Credential cleanup failure raises `CredentialCleanupFailure`, resulting in `AttemptOutcome.INTERNAL_RUNTIME_FAILURE` and blocking proposal canonicalization.
- Redaction pattern covers split secrets and exact credential values across stdout/stderr stream captures.

### Work Package 5 — Qualified Linux Confinement Backend (§8.3–§8.7)
- Implemented `BubblewrapExecutionBackend` in `runtime/confinement.py` utilizing Linux `bwrap`.
- Unshares IPC, PID, UTS, and optionally NET namespaces (`NetworkPolicy.DENY` by default).
- Mounts host `/usr`, `/lib`, `/bin`, `/etc` read-only; mounts task `bundle/` read-only; mounts `output/`, `scratch/`, `home/`, `tmp/`, `credentials/` read-write.
- Protects host canary files, review project roots, and `private/` task provenance from sandboxed worker visibility.
- Confinement qualification gate: `require_real_engine_qualification()` verifies platform capabilities, profile hashes, confinement code fingerprints, and conformance test results. Any mismatch or absent qualification causes real engines to fail closed immediately.

### Work Package 6 — Idempotent Accepted-Task Receipts (§9.1–§9.7)
- Added `AppliedTaskReceipt` and generation metadata `applied_tasks.json` committed atomically inside the writer lock.
- Deterministic `semantic_task_key` computed over engine name, version, configuration, task type, task spec version, handler fingerprint, and inputs (independent of generation number).
- Before starting attempt loop, existing receipts are verified against current snapshot:
  - Base snapshot dependencies and resources must be fresh.
  - Canonical objects generated by the receipt must match their committed hashes in the current snapshot.
  - Proposal is re-validated against current snapshot (`validate_proposal` + `validate_repository`).
  - Current disposition guards are re-evaluated; any divergence triggers fail-closed `ACCEPTED_RECEIPT_REEVALUATION_REQUIRED`.
- On valid receipt match, returns cached `RuntimeResult` immediately with `receipt_reused=True`, skipping worker execution and creating no new IDs or generation.
